Object-Oriented Programming

Classes, objects and inheritance. Up to Chapter 8 our programs were procedural: a list of steps split into functions, with the data kept in separate variables. In OOP we build programs from objects that keep their data and the code that works on it together, like real things.

Part 1: Objects and classes

1.1 Why OOP?

Reusable code

A class written once can be used in many programs.

Cleaner structure

Data and the code that works on it are kept together in one place.

Abstraction

You use an object without worrying how it works inside.

Fewer bugs

A change inside one class does not break the rest of the program.

Key idea: Python fully supports OOP: encapsulation, inheritance and polymorphism. In fact everything in Python is an object: an int, a string, a list, even a function.

1.3 A class is the blueprint

Thousands of cars of the same model are built from one blueprint. In OOP that blueprint is a class. Creating an object from a class is called instantiation, and the object is an instance of the class ("object" and "instance" mean the same thing).

Remember it like this: a class is a cookie cutter, objects are the cookies. One cutter, many cookies, and each cookie can have different toppings (values).

1.4 Defining a class

class ClassName:
    # class body: usually methods

object_name = ClassName()   # instantiation: looks like calling a function

Class names use CapitalisedWords by convention: Circle, BankAccount.

Constructor __init__()

  • runs automatically when an object is created
  • creates and sets the instance variables
  • Circle(5) sends 5 to radius
  • parameters can have default values
  • only one per class: a second __init__ replaces the first

self

  • the first parameter of every method
  • refers to the object itself
  • self.x = this object's data field
  • self.m1() = call another method of this object
  • not passed when calling: c1.get_area() becomes Circle.get_area(c1)

Instance variables & methods

  • created with self.name = value
  • each object has its own copy
  • instance methods are called by an object to work with its own data

Dot operator .

obj.data_field          # read
obj.data_field = value  # change
obj.method(arguments)   # call

Complete example: the Circle class

import math

class Circle:
    """A circle with a radius."""

    def __init__(self, radius=1):    # constructor: runs when an object is created
        self.radius = radius         # instance variable (data field)

    def get_area(self):              # instance method
        return math.pi * self.radius * self.radius

    def get_perimeter(self):
        return 2 * math.pi * self.radius

c1 = Circle(5)          # instantiation: c1 is an object (instance) of Circle
c2 = Circle()           # radius uses the default value 1
print("c1 radius:", c1.radius, " area:", format(c1.get_area(), ".2f"))
print("c2 radius:", c2.radius, " area:", format(c2.get_area(), ".2f"))
c2.radius = 10          # change a data field with the dot operator
print("c2 radius:", c2.radius, " area:", format(c2.get_area(), ".2f"))
print("Different objects?", id(c1) != id(c2))
c1 radius: 5  area: 78.54
c2 radius: 1  area: 3.14
c2 radius: 10  area: 314.16
Different objects? True
CodeWhat happens
class Circle:starts the blueprint
def __init__(self, radius=1)the constructor creates the data field self.radius
get_area, get_perimeterinstance methods use the object's own radius through self
c1 = Circle(5), c2 = Circle()two separate objects; c2 uses the default radius 1
c2.radius = 10changes c2's radius only; c1 is not affected
id(c1) != id(c2)the two objects have different identities
Common mistakes:
  • The constructor name is exactly two underscores, init, two underscores. __init(), _init_() and init__() are ordinary methods that never run automatically.
  • Forgetting self in a method: def get_area(): gives TypeError: get_area() takes 0 positional arguments but 1 was given, because Python always passes the object.
  • Writing radius instead of self.radius inside a method gives a NameError.

Special (dunder) methods: __str__()

Names with two leading and two trailing underscores ("dunder") have a special meaning. __str__() returns a string describing the object; Python calls it automatically for print(obj) and str(obj).

def __str__(self):
    return "Circle with radius " + str(self.radius)

print(Circle(5))    # Circle with radius 5
# without __str__():  <__main__.Circle object at 0x000001F3A2B4C8D0>

Part 2: Variables and objects as arguments

2.1 Scope: instance variables vs local variables

KindCreatedScope (where it can be used)
Instance variable self.xwith self. (usually in __init__)the whole class, in every method
Local variable zinside a method, without self.only inside that method; it disappears when the method ends
class ClassName:
    def __init__(self):
        self.x = 1          # instance variable: usable in m1() and m2()

    def m1(self):
        self.y = 2          # instance variable created here
        z = 5               # local variable: only inside m1()

    def m2(self):
        u = self.x + 1      # OK: self.x is visible
        self.m1()           # call another method of the same object
        # print(z)          # NameError: z belongs to m1() only
Rule of thumb: if a value is needed by more than one method, or must be remembered after the method ends, store it as self.something. A quick calculation inside one method can use a local variable.

2.2 Class variables: shared by every object

class Student:
    school = "Python College"   # class variable: shared by all objects
    count = 0                   # class variable: how many students were created

    def __init__(self, name):
        self.name = name        # instance variable: different for each object
        Student.count += 1      # change the class variable through the class name

s1 = Student("Ali")
s2 = Student("Mei Ling")
print(s1.name, "|", s2.name)        # Ali | Mei Ling        (different)
print(s1.school, "|", s2.school)    # Python College | Python College   (the same)
print("Students created:", Student.count)   # 2
Trap: to change a class variable, use the class name: Student.count += 1. Writing self.count += 1 creates a new instance variable in that one object, and the shared count does not change.

2.3 Objects as arguments

Passed to a functionCan the function change the original?
numbers, strings (immutable)No: it can only make a new value
your own objects, lists (mutable)Yes: the function receives the same object, not a copy
def double(n):            # n is an int: immutable
    n = n * 2

def enlarge(circle):      # circle is an object: mutable
    circle.radius = circle.radius * 2

number = 5
double(number)
print("number after double():", number)     # 5

c = Circle(5)
enlarge(c)
print("radius after enlarge():", c.radius)  # 10

Part 3: Data hiding, getters and setters

3.1 Why hide data fields?

With obj.data_field anyone can read and change an object's data. Two problems:

  • Data can be tampered with: account.balance = -1000000 or circle.radius = -5 would be accepted with no check.
  • Hard to maintain: if other programs use the data field directly, you can't change how the data is stored without breaking them.

Data hiding removes direct access. If a class is designed for other programs to use, make its data fields private.

3.2 Private members: two leading underscores

  • self.__radius, def __helper(self): are private: usable inside the class, not from outside.
  • Don't end the name with two underscores: __radius is private, __radius__ is not (that's a dunder name).

3.3 Getters and setters

MethodAlso calledPurposeNaming
Getteraccessorreturn a data field's valueget_property_name(self)
Getter (Boolean)accessorreturn True or Falseis_property_name(self)
Settermutatorchange a data field, usually after checking the new valueset_property_name(self, value)
class BankAccount:
    def __init__(self, owner, balance=0):
        self.__owner = owner          # private data field
        self.__balance = balance      # private data field

    def get_owner(self):              # getter (accessor)
        return self.__owner

    def get_balance(self):
        return self.__balance

    def set_balance(self, balance):   # setter (mutator) with validation
        if balance >= 0:
            self.__balance = balance
        else:
            print("Error: balance cannot be negative!")

    def is_empty(self):               # Boolean getter: is_...
        return self.__balance == 0

account = BankAccount("Ali", 500)
print(account.get_owner(), account.get_balance())   # Ali 500
account.set_balance(-100)                            # rejected by the setter
print(account.get_balance(), account.is_empty())    # 500 False
print(account.__balance)    # AttributeError: 'BankAccount' object has no attribute '__balance'
Key idea: the setter is the only way in, so it can validate. A field with a getter but no setter is read-only (the owner's name here).
Behind the scenes: Python renames __balance to _BankAccount__balance ("name mangling"). That's why account.__balance fails. Treat private fields as "do not touch from outside".

4.2 Procedural vs object-oriented thinking: BMI three ways

ProceduralObject-oriented
focuses on designing functionsfocuses on objects and the operations on them
data and functions are separatedata and methods are coupled together
related values are loose, separate variablesrelated values live together in one object
  1. No functions: the BMI formula is written straight into the program, so it can't be reused.
  2. A function get_BMI(weight, height): reusable, but the person's name and age are separate variables, easy to mix up with many people.
  3. A class: a BMI object holds name, age, weight and height together, and knows how to compute its own BMI and status.
Spot the bug in the slide version: weight = input(...) without float(), and "{.2f}" without the colon. Both crash: the input is a string, and the format code must be {:.2f}.
class BMI:
    def __init__(self, name, age, weight, height):
        self.__name = name
        self.__age = age
        self.__weight = weight      # kg
        self.__height = height      # metres

    def get_name(self):
        return self.__name

    def get_bmi(self):
        return round(self.__weight / (self.__height * self.__height), 2)

    def get_status(self):
        bmi = self.get_bmi()        # one method calling another through self
        if bmi < 18.5:   return "Underweight"
        elif bmi < 25:   return "Normal"
        elif bmi < 30:   return "Overweight"
        else:            return "Obese"

for person in [BMI("John Doe", 18, 65, 1.75), BMI("Peter King", 50, 97.5, 1.78)]:
    print("The BMI for", person.get_name(), "is", person.get_bmi(), person.get_status())
# The BMI for John Doe is 21.22 Normal
# The BMI for Peter King is 30.77 Obese

4.3 Example: the student with the best GPA

A file has one student per line: name, credit hours and quality points, separated by tabs. GPA = quality points ÷ credit hours.

def make_student(info_str):
    # "Adams, Henry\t127\t228" -> Student("Adams, Henry", "127", "228")
    name, hours, qpoints = info_str.strip().split("\t")
    return Student(name, hours, qpoints)

best = None
for line in infile:
    s = make_student(line)
    if best is None or s.gpa() > best.gpa():   # compare OBJECTS by calling their methods
        best = s
  • make_student() turns one line of text into one object.
  • best starts as None; each new student is compared with s.gpa() > best.gpa().
  • if __name__ == "__main__": main() runs main() only when the file is run directly, not when it is imported as a module.

4.4 Rules of thumb for defining a class

  1. Think about the attributes (data) and behaviour (methods) first.
  2. Choose a good class name and a short list of methods users will need.
  3. Write a short test script that uses the class the way you want.
  4. Choose suitable data types / structures for the attributes.
  5. Start with a constructor and a __str__() method.
  6. Complete and test the other methods one at a time.
  7. Document the code: docstrings for the module, class and every method.

Part 5: Inheritance

5.1 Why inheritance?

Circle, Rectangle and Triangle share many features (colour, filled). Writing each from scratch repeats code, and every fix must be made in many places. Inheritance puts the common features in one general class, then extends it into specialised classes that only add or change what is different.

5.2 Superclass and subclass

General classSpecialised class
superclasssubclass
base classderived class
parent classchild class

A subclass inherits the parent's data fields and methods, and can add new ones and override (change) inherited ones.

is-a → inheritance ✔is-not-a → no inheritance ✘
A lemon is a citrus fruit, which is a fruitA lemon is not a leaf
A shepherd is a dog, which is a mammalA shepherd (dog) is not a human
A circle is a geometric objectA car has an engine (has-a: use a data field, not inheritance)

5.3 Syntax

class DerivedClassName(BaseClassName):
    # class body

class DerivedClassName(module_name.BaseClassName):   # base class in another module
    # class body

A subclass can use everything in the base class, including __init__(). If the subclass has no constructor of its own, it uses the parent's.

The subclasses only list what is new or overridden. Colour, filled and their getters and setters are inherited.

class Circle(GeometricObject):                       # subclass
    def __init__(self, radius=1, colour="green", filled=True):
        super().__init__(colour, filled)              # parent sets colour, filled
        self.__radius = radius                        # new data field

    def get_area(self):
        return math.pi * self.__radius ** 2

    def __str__(self):                                # override, and extend
        return super().__str__() + ", radius: " + str(self.__radius)

5.5 Overriding methods

Overriding = the subclass defines a method with the same name as the parent's; the subclass's version is used for its objects. It can replace the parent's method completely, or extend it (call the parent's version, then add more). Extending is usually better because nothing is written twice.

5.6 super()

super() refers to the parent class without naming it. Most often it calls the parent's constructor so the parent sets up its own data fields.

✘ Without super(): repeat the parent's code
def __init__(self, color, filled, radius):
    self.color = color      # copied
    self.filled = filled    # copied
    self.radius = radius
✔ With super(): reuse the parent's code
def __init__(self, color, filled, radius):
    super().__init__(color, filled)
    self.radius = radius

If the parent's parameters have defaults, super().__init__() with no arguments uses them.

Common mistakes:
  • A subclass writes its own __init__() but forgets super().__init__(): the parent's constructor never runs, so c.colour gives AttributeError: 'Circle' object has no attribute 'colour'.
  • A parent's private field (self.__colour) cannot be used directly in the child. Use the parent's getter: self.get_colour().

Part 6: Investigating inheritance

6.1 isinstance() and polymorphism

isinstance(object, Class) is True if the object belongs to that class or any of its subclasses.

isinstance(circle1, Circle)              # True
isinstance(circle1, GeometricObject)     # True: a Circle IS A GeometricObject
isinstance(circle1, Rectangle)           # False
isinstance(rectangle1, GeometricObject)  # True
def display_object(g):
    print("Area is", format(g.get_area(), ".2f"))           # works for EVERY shape
    print("Perimeter is", format(g.get_perimeter(), ".2f"))
    if isinstance(g, Circle):                                # only circles have a diameter
        print("Diameter is", g.get_diameter())
    if isinstance(g, Rectangle):
        print("Width is", g.get_width(), "and height is", g.get_height())
Polymorphism ("many forms"): the same call g.get_area() runs Circle's version for a circle and Rectangle's version for a rectangle. isinstance() is only needed for the shape-specific extras.

6.2 Multiple inheritance

6.3 Method Resolution Order (MRO)

When an object uses a method, Python searches: the class itself, then its bases depth-first, left to right, never the same class twice. See it with ClassName.mro().

Avenger(Human, Superhero)speak()
Humanspeak()
Superherospeak() · power()
object(every class ends here)
Look up on a = Avenger():
Press a button to watch Python search the MRO: Avenger → Human → Superhero → object.
class Avenger(Human, Superhero):              # multiple inheritance
    def speak(self):
        return Superhero.speak(self) + " " + super().speak()

a = Avenger()
print(a.speak())    # I am a superhero. I am a human.
print(a.power())    # I can fly.        (found in Superhero)
print([c.__name__ for c in Avenger.mro()])   # ['Avenger', 'Human', 'Superhero', 'object']

In speak(), super().speak() goes to Human (the next class in the MRO), while Superhero.speak(self) names its class directly.

isinstance() checks an object against a class. issubclass() checks a class against a class. The attribute is __bases__ (plural) and returns a tuple, because a class can have several parents.

Part 7: Object-oriented design and review

7.1 Finding classes from a problem description

  1. Write a description of the problem.
  2. Underline the nouns, verbs and adjectives.
  3. Nouns → potential classes (or data fields).
  4. Verbs → potential methods.
  5. Adjectives → potential attributes.
  6. Allocate methods and attributes to classes; decide relationships (is-a inheritance, has-a data field); test with use cases.
Problem: A library lends books and DVDs to members. Every item has a title and can be borrowed and returned; an item that is borrowed is unavailable. A book also has an author, and a DVD has a running time. A member has a name and can borrow at most 3 items.
nouns → classes / data fields · verbs → methods · adjectives → attributes
Item    → title, available; borrow(), return_item(), is_available()
├── Book    → + author         (a Book IS AN Item)
└── DVD     → + running_time   (a DVD IS AN Item)
Member  → name, items (a list of Item objects: a Member HAS items)
